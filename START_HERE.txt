SAMARA CARE ERP – PWA UPDATE + SELF-REPAIR FIX
Version: 2.10.05

REPLACE THESE FILES IN THE ERP WEBSITE ROOT
1. index.html
2. service-worker.js
3. bootstrap-error.js
4. app.js

No SQL / Supabase database change is required.

WHAT IS ADDED IN v2.10.05

1. NEW VERSION AVAILABLE PROMPT
When a newer Samara Care ERP version is deployed, the running browser/PWA checks the live service-worker version. If the live version is newer, users see:

  New version of Samara Care is available
  [Update Now]

Tapping Update Now refreshes the installed PWA to the new release.

2. LOGIN PAGE APP HELP
The login page now contains:

  Having trouble opening Samara Care?
  [Reload App]   [App Help / Repair]

3. APP HELP AFTER LOGIN
Mobile Menu contains:
  App Help / Repair
  Check for Updates

Desktop sidebar also contains:
  App Help / Repair

The App Help panel shows the current ERP version and provides:
  Check for Updates
  Reload App
  Repair App

4. STARTUP ERROR RECOVERY
If the ERP fails during startup, the recovery screen provides:
  Reload Samara Care
  Repair App & Reload

5. REPAIR APP SAFETY
Repair App clears only Samara Care PWA Cache Storage and the service-worker registration, then reloads fresh application files.
It does NOT delete or modify Supabase patient, clinical, medication, billing, accounts or other database data.

DEPLOYMENT RULE FOR ALL FUTURE RELEASES
Always increase the version number in ALL FOUR startup files together:
  index.html
  app.js
  service-worker.js
  bootstrap-error.js

Example: 2.10.05 -> 2.10.06
Do not deploy changed app.js code under the same ERP version number. A version increase is what allows already-installed mobile PWAs to detect and display the Update Now prompt reliably.
