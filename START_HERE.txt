SAMARA CARE ERP v2.10.16 — WHATSAPP LOGO HEADER STANDARD
========================================================

PURPOSE
Every normal Samara WhatsApp reply should carry a small Samara logo image with the message as its caption.
Approved Meta templates continue to use their IMAGE header where the template supports IMAGE headers.

REPLACE WEBSITE ROOT FILES
1. index.html
2. service-worker.js
3. bootstrap-error.js
4. app.js

REDEPLOY EDGE FUNCTIONS
1. supabase/functions/whatsapp-send/index.ts
2. supabase/functions/whatsapp-webhook/index.ts

NO SQL CHANGE.

STANDARD LOGO URL
https://samaraassistedliving.com/assets/samara-logo.png

WHAT CHANGED
- ERP direct WhatsApp replies inside the 24-hour service window are now properly supported as IMAGE + caption messages.
- Automatic replies to General Follow-up buttons (Our Location, Request a Call, Admission Details) now send the Samara logo with the response as caption.
- ERP template sends continue supplying the Samara logo as IMAGE header by default.
- Version bumped to 2.10.16 so installed mobile PWAs can receive the update prompt independently.

META TEMPLATE RULE
For templates such as General Follow-up, Package Expiry, Emergency, Admission, Payment, etc., the Meta template itself must have Header type = IMAGE. The ERP cannot add an IMAGE header to a Meta template that was approved without one.

IMPORTANT EXCEPTION — DAILY PATIENT REPORT
samara_daily_patient_report uses Header type = DOCUMENT because the Intelligent Patient Care Report PDF is attached there. WhatsApp templates cannot use IMAGE and DOCUMENT header media at the same time. Keep the Samara logo inside the PDF itself; do not change that template to IMAGE.

OPTIONAL EDGE FUNCTION SECRET
SAMARA_WHATSAPP_LOGO_URL=https://samaraassistedliving.com/assets/samara-logo.png
If omitted, the same URL above is used automatically by whatsapp-webhook.
