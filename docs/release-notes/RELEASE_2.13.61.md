# Samara ERP 2.13.61 — durable discharge history and late departure review

New billing after Accounts clearance previously erased the clearance actor and timestamp. The previous clearance now remains visible, each clearance and recheck has a permanent event record, and the register labels a financial recheck explicitly. Nursing sees workflow history; financial details remain restricted to Accounts and management. Existing erased timestamps are labelled unavailable, never reconstructed.

Nursing can report a patient who already left, with actual departure time and a late-entry reason. Admin/Director reviews a fresh snapshot of automatic charges after the reported departure date and any recorded subsequent clinical activity. Approval keeps the original charges and posts individually linked reversal credits, blocks duplicate corrections, and sets the accommodation billing cutoff. The departure date itself remains billable under the existing daily billing rule. Genuine extended stays continue to accrue daily charges. Original charges and their reviewed correction entries become immutable audit records. The existing ledger represents reversal credits using the Discount transaction type and the separate Post-departure Billing Correction category; no payment or refund is created.

Accounts must verify the resulting balance and resolve pending charges before clearance. Nursing retains final handover, actual departure confirmation and bed release. Final completion records actual departure and entry time separately, requires a reason for entries over one hour late, and rejects future times or dates inconsistent with an approved correction. Open clearances appear in a Nursing/management follow-up banner; waits over two hours are flagged for Nursing Manager/Admin attention. These are in-app reminders, not external messages.

Deployment: apply `131_discharge_history_and_departure.sql`, then publish `app.js`, `discharge-workflow.js`, `index.html`, `service-worker.js`, this migration and release note together. Reload the ERP. The migration seeds only existing verifiable history; it does not reverse charges, grant clearance, approve a departure report, or discharge any patient.

Validation: isolated PGlite tests using production table shapes and captured current function definitions cover migration retry, clearance preservation, discarded duplicate inserts, no-op updates, positive-balance and unresolved-charge blocking, role restrictions, Nursing financial redaction, invalid/future/duplicate reports, stale review rejection, later clinical activity warnings, idempotent correction, original/credit immutability, reviewed cutoff and catch-up verification, re-clearance, mandatory late reason, fixed reviewed departure time, final Nursing completion, separate recording time, bed release, and a later admission. JavaScript syntax and whitespace checks pass. Synthetic browser checks cover management approval controls, warning/confirmation states and mobile layout; a component test validates the Nursing report payload in IST. No test payment, correction, clinical entry or discharge is executed in production.

Operational limitation: the ERP cannot infer physical departure from management approval or Accounts clearance. Nursing must report the real time; management must reconcile conflicting later clinical entries before approving a correction. Earlier clearance metadata that was already erased cannot be restored without independent evidence.
